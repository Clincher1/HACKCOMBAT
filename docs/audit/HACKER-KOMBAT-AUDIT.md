## 2. Игровая петля, экраны и «что делает игрок»

### 2.1 Ядро петли (30 секунд)
1. **Тап по устройству** (ноут/телефон в сцене) → +Data и +Energy-расход? Нет: тап даёт **Data** и тратит **Energy**; Energy регенит 1 ед./2 сек.
2. **Data** — оборотный капитал: им платят за карточки, взносы за миссии, апгрейды Базы, корм питомцев, найм части команды.
3. **Взлом (миссия)** — стоит Energy (= длительность в секундах) + Data-взнос (12% награды). Через N секунд игрок «забирает» результат; бросок исхода происходит на сервере: успех / частичный успех / провал.
4. **XP от миссий** → уровень → слоты миссий (1 → 2 на 10 ур. → 3 на 20 ур.), тиры карточек, звания, доступ к контенту.
5. **Чипы (Chips)** — «премиальная» валюта прогресса: падают по 1 за контракт, 2 за серый контракт, 3 за ежедневку; кап 45/сутки. Тратятся на уровни карточек выше 15-го и на апгрейды Базы.
6. **Crypto (💎)** — валюта косметики: скины, рамки, локации; падает с серых контрактов (35% базово) и за достижения; за престиж не сбрасывается.
7. **Rep / Heat** — репутация и розыск. Их соотношение задаёт «выравнивание» (white_hat / neutral / black_hat) с бонусами.

## 3. Архитектура и инфраструктура

### 3.1 Слои
```
shared/*.config.ts   ← единственный источник правды по контенту и формулам (импортируется И клиентом, И сервером)
src/                 ← React SPA, вызывает /api/* через src/lib/api.ts
api/[...path].js     ← одна serverless-функция; собирается из api/_routes/*.ts + api/_lib/* через scripts/bundle-api.mjs в api/_core.cjs
supabase/            ← SQL-миграции (001…018) + RLS + атомарные RPC
```

Ключевое архитектурное решение: **вся логика начисления — на сервере**. Клиент может рисовать любые цифры, но Data/XP/Heat/чипы меняются только в `gameEngine`. Шанс успеха миссии фиксируется в БД **на старте** (поле `missions.success_chance`), поэтому «подкрутить» исход после таймера нельзя.

### 3.2 Режимы работы
- `mode = 'supabase'` — обычный прод-режим (данные в Postgres).
- `mode = 'memory-fallback'` — если нет `SUPABASE_URL`/`SUPABASE_SERVICE_ROLE_KEY`: игра работает на локальном JSON-файле (`.local-db.json`), прогресс теряется. Именно этот режим был на проде до подключения Supabase — риск, который мы закрыли.

### 3.3 Аутентификация
- Заголовок `X-Telegram-Init-Data` ← `Telegram.WebApp.initData`, проверяется HMAC-SHA256 по `BOT_TOKEN` (`api/_lib/telegramAuth.ts`).
- Без Telegram: заголовки `X-Demo-User-Id` / `X-Demo-Username`, из них выводится **изолированный guest-id** (`deriveIsolatedGuestId`). Включается только если `STRICT_TELEGRAM_AUTH !== 'true'`.
- Итог: бот отдаёт реальные аккаунты, браузер — гостевые (не пересекаются с Telegram-игроками).

### 3.4 Защита API (`api/_lib/http.ts`)
| Механизм | Значение |
|---|---|
| Лимит тела запроса | 16 КБ |
| Rate-limit по IP | 900 запросов / 60 с |
| Rate-limit по игроку | 600 запросов / 60 с |
| Бакеты | in-memory, до 20 000 ключей, окно 60 с, `Retry-After` в ответе |
| CSRF | POST разрешён только с того же хоста, `PUBLIC_WEBAPP_URL`, `*.e2b.app`, `localhost`; `/api/telegram` исключён (вебхук) |
| Заголовки | `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy` |
| Клики | `sanitizeClicks()` — максимум **60 кликов за запрос**, дальше пачка режется и логика античита считает «клики/сек» |

### 3.5 Деплой и переменные окружения
| Переменная | Назначение | Статус на проде |
|---|---|---|
| `BOT_TOKEN` | проверка initData, вебхук бота, донаты | задан (проект `hacker-kombat`) |
| `SUPABASE_URL` | Postgres/REST | задан |
| `SUPABASE_SERVICE_ROLE_KEY` | серверный доступ к БД (RLS обходится только на сервере) | задан |
| `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` | клиентский supabase (публичный anon) | заданы |
| `PUBLIC_WEBAPP_URL` | публичный адрес для ссылок/вебхука | задан |
| `ADMIN_TG_IDS` | админы бота (доноры/модерация) | задан |
| `REFERRAL_CODE_SALT`, `REFERRAL_IP_SALT` | соль для кодов и хэша IP в рефералке | заданы |
| `STRICT_TELEGRAM_AUTH` | если `true` — гостевой вход запрещён | **не задан** (гости разрешены) |
| `TELEGRAM_WEBHOOK_SECRET` | если не задан — выводится HMAC из токена | не задан (выводится) |
| `DONATE_CARD_URL`, `DONATE_CARD_LABEL` | внешний донат-линк (СБП/карта) | не заданы |

Инфраструктурные особенности Vercel-проекта: `ssoProtection = all_except_custom_domains`, `nodeVersion 24.x`, `functionTimeout 300`, регион `iad1`, кэш сборки ~39 МБ.

## 4. Экономика и формулы

### 4.1 Валюты и ресурсы

| Ресурс | Как получить | Куда тратить | Сбрасывается престижем |
|---|---|---|---|
| **Data** | тап, пассив карточек/команды, миссии, ежедневки, оффлайн-копилка | карточки, взносы миссий, «База», найм NPC (часть), корм питомцев | **да** |
| **Energy (⚡)** | 1 ед./2 с, макс 1500 → 5000 (карточки comfort), кофемашина +50% | взнос за миссию = секунды контракта | нет (сбрасывается в макс) |
| **XP** | только миссии (и немного дейлики/рефералка) | уровень, слоты миссий, тиры | **да** |
| **Chips** | 1/миссия, 2/серая, 3/ежедневка, кап 45/сутки | уровни карточек >15, апгрейды Базы | нет |
| **Crypto (💎)** | серые контракты (35%), достижения, донаты | скины, рамки, локации, «скан сети» (skip миссии — 1 💎) | нет |
| **Rep** | «белые» миссии за плохих ребят | выравнивание white_hat, статистика | да |
| **Heat** | «серые»/агрессивные миссии | (анти-ресурс) штрафы, black_hat | да |
| **Prestige multiplier** | Global Hack | множитель клика и пассива | — |

### 4.2 Уровень и опыт
```
xpToNext(L) = max(50, round(140 · L^2 / 10) · 10)
totalXp(L)  = 140 · n(n+1)(2n+1)/6,  n = L − 1
```
Уровень определяется **только накопленным XP**, деньги на уровень не влияют. Потолка нет.

### 4.3 Клик (тап)
```
clickMultiplier = (1 + Σ cardClickBonus·incomeMult(lvl))
                × (1 + teamClick% + blackHat(0.5) + skin% + baseClick% + petClick%)
                × prestigeMultiplier
clickPower = max(1, round(clickMultiplier × 10) / 10)
```
- База (0 карточек, 0 команды, 0 скинов): **10 Data за тап**.
- Потолок бонуса скинов: `SKIN_CLICK_BONUS_CAP = 0.22` (три слота суммируются, но не больше 22%).
- `black_hat` даёт +50% к клику и +30% к приросту Heat.

### 4.4 Пассивный доход
```
dataPerHour = round( Σ card.dataPerHourPerLevel · (1.18^lvl − 1)/0.18
                     × (1 + teamPassive + whiteHat(0.2) + basePassive + petPassive)
                     × prestigeMultiplier
                   + autoClickPerSec · clickPower · 3600 )
```
- Авто-клик: Ботмастер (1/с) + Спектр (1/с) + авто-скрипт Базы (до 2/с), но **не больше 5/с** суммарно.
- Оффлайн: пассив ×0.5, плюс 0.1 тапа/с × clickPower, кап 8 ч (+10 ч ИБП).

### 4.5 Миссии (взломы)
Награда фиксируется на старте:
```
reward = baseDataReward × rewardScale(level) × whiteHat(×2 на bad) × prestigeMultiplier × (1 + missionRewardBonus)
rewardScale(L) = exp( (min(L,90) − 1)·ln(1.14) + max(0, L − 90)·ln(1.02) )
entry  = { data: max(25, ceil(reward × 0.12)), energy: durationSec }
```
- Взнос **не возвращается** даже при провале — это цена подготовки.
- Шанс успеха — раздел 5.5, формула в 4.6.
- Исходы: `success` 100% лута и 1 чип; `partial` 45% Data / 55% XP / 50% Rep / 50% Heat, 0 чипов; `fail` 0 Data / 15% XP / 1.5× Heat, 0 чипов.
- XP: `xpReward × (xpToNext(level)/xpToNext(refLevel))^0.9 × 0.85^перерост`, refLevel = 1/3/7/12/18/26 для тиров 1–6.

### 4.6 Шанс успеха
```
chance = baseSuccess
       × clamp(0.5 + 0.5 · hackPower/requiredPower, 0.55, 1.25)
       × clamp(0.72 + 0.28 · level/minLevel,      0.72, 1.12)
       × clamp(1 + 0.02·успехи_типа − 0.04·провалы_типа, 0.70, 1.15)
       × clamp(1 − heat/250,                       0.72, 1.00)
       → clamp(chance, 0.05, 0.96)

hackPower = 10 + Σ уровней карточек · 1.6 + Σ hackPower команды + Σ уровней Базы · 3 + престиж · 40
baseSuccess: neutral 0.90 · bad 0.88 · good 0.76 · grey 0.64
```
Опыт по типу цели: каждый успех +2% к шансу, каждый провал −4%.

### 4.7 Карточки
```
price(card, lvl) = floor( basePrice · 1.24^lvl · priceScale · globalIndex · (1 − discount) )
priceScale  = 1 + 39·w
globalIndex = 1 + ((1 + totalCardLevels/50)^1.2 − 1)·w
w           = clamp(1 − log10(basePrice/20)/6, 0, 1)      // дешёвые карточки дорожают сильнее
incomeMult(lvl) = (1.18^lvl − 1) / 0.18
```
- `MAX_CARD_LEVEL = 60`, тиры 15/30/45/60 с гейтами по уровню игрока 1/10/22/36 и оплатой чипами 0/60/150/320 + Data 0 / 120 тыс. / 1,5 млн / 12 млн.
- Скидка «Термопласта» (База) — до 25%.

### 4.8 «База» (пассивные апгрейды)
`price = basePrice · priceGrowth^lvl` + чипы `baseChipCost` за уровень. Не сбрасывается престижем. Суммарные эффекты зажаты потолками: реген +50%, клик +25%, −Heat 40%, авто-клик 2/с, оффлайн +10 ч, награда миссий +30%, пассив +30%, скидка карточек 25%, корм −40%, шанс Crypto +20%.

### 4.9 Питомцы
Баф работает только при сытости: ≥60 — 100%, 30–60 — 50%, <30 — 0%. Привязанность (5 кормлений = 1 уровень, до 10) даёт до +27% к бафу. Суммарные бафы зажаты: пассив/клик/миссии ≤30%, −Heat ≤40%.

### 4.10 Престиж (Global Hack)
- Доступен с **50 уровня**, потом каждые +10 уровней (60, 70, …).
- Множитель: первые 5 циклов ×2 каждый (×2…×32), дальше +10% за цикл.
- Сбрасывает карточки, Data, XP/уровень, Heat/Rep, тир карточек, активные миссии.
- Сохраняет: Crypto, чипы, скины/рамки/локации, достижения, Базу, команду, питомцев, статистику, сезон.

### 4.11 Heat, штрафы, выравнивание
- Heat > 100 → потеря 10% Data, Heat → 50, блок кликов 60 с.
- `white_hat`: `rep ≥ 10 && rep > heat·2` → +20% пассива, ×2 Data и Rep за «плохие» цели.
- `black_hat`: `heat ≥ 10 && heat > rep·2` → +50% клика, ×1.3 к приросту Heat.
- Снижение Heat: Фантом −20%, Шифр −10%, Спектр −5%, VPN-роутер −1%/ур. (макс −40%, общий кап −70%).

### 4.12 Ежедневки, инциденты, сезон, рефералка, донаты
- **Ежедневный бонус**: стрик (поле `daily_streak`), сброс при пропуске.

#### Шанс успеха

`chance = baseSuccess × gearFactor × levelFactor × experienceFactor × heatFactor`, зажатый в 0.05..0.96:

- `gearFactor = clamp(0.5 + 0.5 · hackPower/requiredPower, 0.55, 1.25)`
- `levelFactor = clamp(0.72 + 0.28 · level/minLevel, 0.72, 1.12)`
- `experienceFactor = clamp(1 + 0.02·успехи_типа − 0.04·провалы_типа, 0.70, 1.15)`
- `heatFactor = clamp(1 − heat/250, 0.72, 1)`
- `hackPower = 10 + Σуровней_карточек·1.6 + ΣhackPower_команды + Σуровней_базы·3 + престиж·40`

Исходы: `success` — полный лут; `partial` — 45% Data / 55% XP / 50% Rep / 50% Heat / 0 чипов; `fail` — 0 Data / 15% XP / 1.5× Heat. Частичный успех занимает 45% от остатка риска: при chance 0.9 → 4.5% partial / 5.5% fail; при 0.5 → 22.5% / 27.5%.

Опыт с контракта: `xpReward × (xpToNext(level)/xpToNext(refLevel))^0.9 × 0.85^{перерост}`, где refLevel = 1/3/7/12/18/26 для тиров 1–6, а перерост считается после 3/7/12/18/26/200 уровня. То есть фарм старых тиров на высоком уровне режется, но не обнуляется (минимум ×0.02).

## 6. Прогрессия и симуляция баланса

### 6.1 Что говорит встроенный симулятор (`npm run balance:sim`)
Модель: **8 часов активной игры в сутки, 60 суток**, старт — 1 уровень и 1500 Energy.

```
Уровень игрока (чистое модельное время):
  Ур.  2: 0.01 дн. (0.1 ч)      Ур. 15: 3.01 дн. (72.2 ч)
  Ур.  5: 0.02 дн. (0.6 ч)      Ур. 20: 5.01 дн. (120.3 ч)
  Ур. 10: 1.01 дн. (24.4 ч)     Ур. 26: 11.01 дн. (264.4 ч)
  Ур. 12: 2.00 дн. (48.0 ч)     Ур. 30: 16.23 дн. (389.4 ч)
                                Ур. 40: 33.04 дн. (792.9 ч)
Prestige #1: 49.11 дн.; #2…#7: не достигнуты за 60 суток.
Суммарные уровни карточек: 25 lvl — 1.0 дн., 50 — 3.0 дн., 75 — 4.0 дн., 100 — 5.05 дн., 150 — 11.0 дн.
Итог 60 суток: ур. 54, XP 7 287 135, миссий 13 291, карточек 442 уровня, Tier 3, prestige 1, ×2.
```

### 6.2 Как это читать
| Вывод | Числа | Что значит |
|---|---|---|
| Вход в игру очень быстрый | ур. 5 — за **36 минут**, ур. 10 — за **~24 часа** | первые 10 минут дают много дофамина, это хорошо для ретеншена |
| Первый «настоящий» гейт | ур. 10 (2-й слот миссий), ур. 20 (3-й слот) | к 2-м и 5-м суткам соответственно |
| Первый престиж | **~49 суток** по модели | для 12+ аудитории это долго; на проде максимум игрока — 23 уровень (см. §11) |
| Карточки: основной темп | 100 суммарных уровней за 5 дней | прогресс карточек быстрее, чем уровни игрока → растёт разрыв «железо сильнее уровня» |
| Миссий за 60 дней | **13 291** (≈ 221/сутки) | модель гоняет миссии без пауз; живой игрок делает 5–20/сутки |
| «Data/час 1 322 178 030» | число из симулятора | **аномалия**: либо баг вывода (пассив×престиж×авто-клик), либо реальный перекос. Требует проверки (см. §11.1) |

### 6.3 Темп по миссиям (на «своём» уровне)
| Уровень | Контрактов тира 3 до следующего уровня (xp=156) | 3 слота параллельно ≈ часов |
|---:|---:|---:|
| 1 | 1 | < 0.1 ч |
| 5 | 23 | ~0.3 ч |
| 10 | 48 | ~0.7 ч |
| 20 | 200 | ~3 ч |
| 30 | 1096 | ~17 ч |
| 50 | 3272 | ~50 ч |
| 100 | 3744 | ~58 ч |

(участник считает «параллельно по 3 слота», длительность — 160 с на контракт тира 3.)

### 6.4 Окупаемость карточек (условно «за сколько часов пассив отобьёт цену»)
| Карточка | Цена 1-го ур. | Прирост Data/ч за 1 ур. | Окупаемость |
|---|---:|---:|---:|
| `monitor` Монитор IPS 240Hz | 800 | ~120 | ~7 ч |
| `keyboard` Мех. клавиатура | 600 | ~80 | ~8 ч |
| `gpu` Видеокарта | 2 720 | ~340 | ~8 ч |
| `server_rack` Серверная стойка | 8 517 | ~950 | ~9 ч |

Практически все ранние карточки окупаются за **7–9 часов** пассива (то есть меньше, чем за сутки с оффлайн-копилкой). Это очень щедро: смысла «выбирать, что купить» нет — покупается всё подряд. Дальше цена растёт ×1.24 за уровень, а доход ×1.18, поэтому к 20–30 уровню окупаемость уходит в дни.

### 6.5 Бюджеты (сколько всего можно получить в сутки)
| Источник | Оценка в сутки | Комментарий |
|---|---|---|
| Пассив карточек | зависит от билда, к 25 уровню карточек — сотни тысяч Data/ч | главный источник после 2-го дня |
| Оффлайн-копилка | до 8 ч × 0.1 тапа/с × clickPower (+пассив ×0.5) | требует 8 минут активности в тот же день |
| Миссии | 3 слота × 24/сутки теоретически; живой игрок 5–20 | ограничение — Energy (взнос = длительность) и взносы Data |
| Ежедневки | 3 задания × 10–40 XP | плюс ежедневный бонус со стриком |
| Чипы | **45/сутки кап** | 42 контракта или 15 ежедневок |
| Crypto | серые контракты 35% + достижения | не фармится бесконечно |

### 6.6 Где узкие места (по цифрам)
1. **Energy — главный лимитер миссий.** Взнос = длительность в секундах; при 1500 Energy и 3 слотах игрок упирается после ~1500 секунд контрактов (25 минут) и ждёт реген. Кофемашина (до +50%) и карточки comfort — обязательны.
2. **Взнос Data = 12% награды** при 0 Data на старте — новичок должен 2–3 раза тапнуть, чтобы запустить первый контракт. Это нормально, но в связке с провалом (0 Data) может ощущаться наказанием.
3. **Комфорт-карточки** дают максимум Energy, но не доход → в начале игры их покупают редко, значит лимит Energy давит долго.
4. **Разрыв «уровень vs карточки»:** к 5-му дню 100 уровней карточек против 12–15 уровня игрока → шансы миссий перекачаны, интерес к «подготовке» падает.
5. **Престиж через 49 дней** — на реальной базе (237 игроков, максимум 23 уровень) не достижим вовсе. Первый Global Hack фактически невидим для игрока.

## 7. API-контракт (серверная часть)

Базовый URL — тот же домен, что и клиент. Все ответы JSON, ошибки в формате `{ ok: false, error: string, retryAfterSec?: number }`. Авторизация — заголовки `X-Telegram-Init-Data` и/или `X-Demo-User-Id` / `X-Demo-Username`.

| Endpoint | Метод | Тело / query | Что делает сервер | Ключевые ограничения |
|---|---|---|---|---|
| `/api/init` | POST | `{ startParam? }` | создаёт/читает игрока, синхронизирует Energy, применяет пассив + оффлайн-копилку, отдаёт `ApiSyncResponse` (state + derived + слоты миссий) | вызывается при каждом входе и после каждого действия |
| `/api/click` | POST | `{ clicks }` | пачка тапов: +Data, −Energy, античит по кликам/сек и по Energy, обновляет `total_clicks` | ≤60 кликов за запрос, ≤600 запросов/мин на игрока |
| `/api/missions` | POST | `{ action: start \| claim \| skip \| refresh, missionKey?, missionId?, clicks? }` | старт (списание Energy+Data, фиксация `success_chance`), клейм (бросок исхода, лут), skip (−1 💎), refresh (скан сети) | миссия должна быть в витрине игрока, серая — только с Ирис, ≤3 активных |
| `/api/buy-card` | POST | `{ cardKey, clicks? }` | покупка следующего уровня карточки, гейты по тиру и чипам | цена считается на сервере |
| `/api/base` | POST | `{ upgradeKey, clicks? }` | покупка уровня «Базы» | уровень, чипы, цена — на сервере |
| `/api/tier` | POST | `{ clicks? }` | переход на следующий тир карточек (чипы + Data + уровень игрока) | 4 тира, дальше «макс» |
| `/api/hire` | POST | `{ npcKey, clicks? }` | наём NPC: списание Data/Rep, требования по уровню и числу миссий | 8 NPC, без дублей |
| `/api/pets` | POST | `{ action: buy \| feed, petKey, clicks? }` | покупка/кормление питомца (голод, привязанность, цена корма от дохода) | куллдаун кормления, авто-корм с Базы |
| `/api/skin` | POST | `{ action: buy_or_equip \| clear_lockdown \| set_theme \| set_backdrop \| profile_frame, skinKey, clicks? }` | косметика: скины трёх слотов, темы, локации, рамки профиля | стоимость в 💎, требования престижа/уровня |
| `/api/inventory` | POST | `{ action: 'set_public', itemKey, visible, clicks? }` | витрина инвентаря в публичном профиле | только «свои» предметы |
| `/api/daily` | POST | `{ clicks? }` | ежедневный бонус + стрик | раз в московские сутки |
| `/api/daily-tasks` | POST | `{ action: 'claim', taskKey, clicks? }` | клейм выполненного ежедневного задания | 3 задания/сутки, детерминированный пул |
| `/api/daily-incident` | POST | `{ choiceKey, clicks? }` | решение инцидента дня (Data/Heat/Rep/Crypto) | один выбор в сутки, повторный — отклоняется |
| `/api/season-event` | POST | `{ action: claim_participation \| claim_mastery, clicks? }` | выдача рамок сезона | 1 полный день / все 7 дней |
| `/api/prestige` | POST | `{ clicks? }` | Global Hack: сброс прогресса, +престиж, выдача скина | требуется 50+10·N уровень, подтверждение |
| `/api/leaderboard` | GET | `?sort=data\|xp\|level` | топ игроков (view `leaderboard`) + своя позиция | публично, без приватных полей |
| `/api/profile` | GET | `?profileId=<id>` | публичный профиль: звание, команда, витрина, косметика | нельзя получить чужой приватный инвентарь |
| `/api/referral` | GET / POST | POST `{ }` | GET — статистика и код; POST — создать/прочитать код и ссылку | лимиты 3/сутки, 10/нед |
| `/api/donate` | GET / POST | POST `{ stars }` | GET — витрина сумм и username бота; POST — инвойс Telegram Stars | 1…1000 ⭐, идемпотентность по charge_id |
| `/api/track` | POST | `{ event, value? }` | продуктовая аналитика (вкладки, туториал, сессии) | 30 событий/сутки на игрока |
| `/api/ping` | GET | — | health-check (есть ли Supabase) | без авторизации |
| `/api/telegram` | GET / POST | GET `?action=register`; POST — вебхук Telegram | регистрация вебхука/команд/меню-кнопки; обработка `/start`, `/invite`, `/donate`, `/help`, платежей | `secret_token` выводится HMAC-SHA256 из `BOT_TOKEN` |

### 7.1 Формат ответа синхронизации
Все мутирующие ручки возвращают один и тот же конверт (`ApiSyncResponse`):
```jsonc
{
  "ok": true,
  "state": { /* PlayerState: data, crypto, chips, xp, energy, heat, rep, cards, team, pets, baseUpgrades, stats, activeMissions, availableMissionKeys, inventory... */ },
  "derived": { /* DerivedStats: level, hackPower, clickPower, dataPerHour, maxEnergy, missionSlots, prestigeMultiplier, rankTitle... */ },
  "leaderboardRank": 12
}
```
Клиент не считает экономику: он только отображает `state` + `derived` и отправляет действия.

### 7.2 Античит (что реально защищено)
| Вектор | Защита |
|---|---|
| Нарисовать себе Data/XP на клиенте | всё считается на сервере, клиент не присылает баланс |
| Подделать Telegram-пользователя | HMAC-SHA256 `initData` по `BOT_TOKEN` |
| Подкрутить шанс успеха после старта миссии | `success_chance` пишется в БД на старте, `outcome` бросается на клейме |
| Двойной клейм одной миссии | атомарный RPC `claim_mission_atomic` + статус миссии |
| Двойная покупка/списание | `commit_purchase_atomic` (CAS по ожидаемому состоянию) |
| Параллельный старт миссий на один баланс | `start_mission_atomic` (CAS по Data/Energy) |
| Макро-кликер | лимит 60 кликов/запрос + проверка кликов/сек + Energy |
| Чужой сайт дёргает API | проверка `Origin` на POST (кроме `/api/telegram`) |
| Флуд | 900 req/мин на IP, 600 req/мин на игрока |
| Мусор в прогрессе (NaN/Infinity/огромные числа) | зажим в `MAX_SAFE_*`, `safeDataBalance`, ограничение уровней карточек |

### 8.2 Поведение, важное для баланса
- **Оптимистичные тапы:** клики накапливаются в очереди и улетают пачками по 60; сервер — источник правды, но UI не «залипает».
- **1-секундный тик:** пассив начисляется локально для плавности (`dataPerHour/3600`), Energy регенит по shared-модели; раз в 30 с — сверка с сервером.
- **Скрытая вкладка:** тик останавливается, при возврате (пауза ≥60 с) — принудительный init и попап «пока вас не было» с оффлайн-копилкой.
- **Очередь действий:** повторные действия по одному ключу блокируются (`queuedActionKeysRef`), чтобы двойной тап не отправлял две покупки.
- **Аналитика:** события `tab`, `tutorial_open`, `tutorial_tab`, `session`, `idle_15`, `local_hour`, `shop_freeze_30` — из них собираются достижения-«пасхалки» (ночная смена, дзен-режим, кофе-брейк).

### 8.3 Визуальный стиль (актуальный, v5.1)
- **Не киберпанк.** Базовая тема `classic` «Сан-Мираж»: тёплый закат, терракота, янтарь, бирюза. Неон — опциональный скин.
- **Локации — фотореалистичные тёплые сцены** (8 шт.), с погодными состояниями (sunset/day/night/rain) и подписью «место · температура · время».
- **Портреты команды:** лица скрыты — капюшон, кепка с низким козырьком, шарф, тень от контрового света. 8 WebP по 19–35 КБ.
- **Палитра:** CSS-переменные `--ui-primary`, `--ui-secondary` и `rgba(var(--ui-*-rgb), α)`; в Tailwind 4 нельзя использовать `bg-[var(--ui-primary)]/18` — только `color-mix()`/inline-style.
- **Шрифты/иконки:** системный стек + эмодзи-глифы для карточек (`iconGlyph`), SVG для категорий.

### 8.4 Мобильный опыт (Telegram Mini App)
- Всё в один столбец, нижняя навигация, крупные тап-зоны, `expandViewport()`, безопасные отступы Telegram.
- Тап по ноуту/телефону — основное действие; на телефоне сцена масштабируется, девайс подсвечивается.
- Звук по умолчанию мягкий, вибрация через `hapticFeedbackImpactOccurred` (fallback — `navigator.vibrate`).
- Тёмная тема Telegram не ломает тёплую палитру: переменные переопределяются на `[data-theme]`.

### 8.5 Тексты и тон
Тон — «чиловый человеческий»: без «нейросетей-убийц», «орбитальных станций» и «квантовых синдикатов». Контракты описывают реальные жизненные схемы (магазин-однодневка, ферма спам-звонков, копия входа в банк), локации — реальные места. Остались единичные легаси-названия (см. §11.3).

### 8.6 Производительность
- Бандл 329,6 КБ / 103,6 КБ gzip — нормально для Mini App.

Именно из-за jsonb-подхода миграции под новые фичи **не нужны** — новые поля просто появляются в `stats`.

### 9.3 Атомарные RPC (security definer)
| Функция | Аргументы (смысл) |
|---|---|
| `init_player(tg_id, username)` | создать/найти игрока, вернуть запись |
| `start_mission_atomic(...)` | CAS по Data/Energy, вставка миссии, списание взноса |
| `claim_mission_atomic(...)` | CAS по всем балансам, запись исхода и лута |
| `commit_purchase_atomic(...)` | CAS-покупка карточки/апгрейда/питомца/найма |
| `global_prestige_atomic(...)` | сброс прогресса и начисление престижа одной транзакцией |
| `distribute_passive_income()` | начисление пассива по расписанию (cron/ручной вызов) |
| `give_new_year_candy_to_new_player()`, `use_new_year_candy(...)` | сезонный предмет |
| `remove_retired_snus_from_player()` | чистка устаревшего предмета |

Смысл: ни одна операция «деньги/предмет» не делается двумя отдельными UPDATE — иначе двойной тап клиента или гонка двух инстансов Vercel могли бы списать баланс дважды.

## 11. Наблюдения аудита (что не так и где риски)

Формат: **F-номер · severity (P0 критично / P1 важно / P2 косметика) · факт → почему это проблема → что делать.**

### 11.1 Баланс и экономика

**F1 · P0 · «Data/час 1 322 178 030» в симуляторе.**
`npm run balance:sim` на 60-й день печатает пассив **1,32 млрд Data/час** при 54 уровне и 442 уровнях карточек. Даже с учётом престижа ×2 и авто-клика это на 2–3 порядка больше, чем даёт арифметика `dataPerHour` (карточки × prestige). Либо в симуляторе ошибка вывода/двойного учёта, либо в `computeDerivedStats` пассив умножается дважды. Пока не проверено кодом — **не считать это балансом**, но и игнорировать нельзя: если баг реальный, вся экономика после 20–30 уровня карточек ломается.
→ Проверить `dataPerHour` на реальном сейве (237 игроков, топ: 9–12 млн Data), сравнить с моделью.

**F2 · P1 · Первый престиж — через ~49 суток игры.**
Модель: престиж #1 на 49-й день при 8 ч/сутки. На живой базе максимум 23 уровень и **0 престижей**. Механика Global Hack — главный долгосрочный крючок — для игрока не существует.
→ Либо снизить порог первого престижа (например 30 уровень), либо ввести «мини-перерождение» на 25 уровне с меньшим множителем, либо ускорить XP-кривую после 20 уровня (сейчас `140·L²`).

**F3 · P1 · Карточки окупаются за 7–9 часов — выбора нет.**
Монитор (800 Data) отбивается за ~7 ч пассива, клавиатура (600) за ~8 ч. Игрок покупает всё подряд, «билд» не складывается, стратегии нет.
→ Поднять цену первых уровней в 2–3 раза **или** снизить `dataPerHourPerLevel` у дешёвых карточек; окупаемость 20–30 ч делает выбор осмысленным.

**F4 · P1 · Energy — жёсткий и неочевидный лимитер.**
Взнос за миссию = её длительность в секундах. При 1500 Energy и трёх слотах игрок «выгорает» за ~25 минут контрактов и ждёт реген 1 ед./2 с. Комфорт-карточки (максимум Energy) при этом не дают дохода — новичок их игнорирует.
→ Дать +Energy за уровень игрока (например +25/уровень) или снизить коэффициент взноса до 0.7×длительности.

**F5 · P1 · Разрыв «карточки vs уровень» растёт.**
К 5-му дню 100 суммарных уровней карточек против 12–15 уровня игрока → `hackPower` в разы выше `requiredPower` → шанс упирается в потолок 0.96, риск исчезает, «подготовка к взлому» перестаёт быть механикой.
→ Привязать `hackPower` к уровню (например мягкий штраф за «слишком сильное железо» на низком уровне) или поднять `requiredPower` эндгейм-миссий.

**F6 · P2 · Числа растут очень быстро после 50 уровня.**
`rewardScale` = 1.14^L до 90 уровня (≈ ×1.1e5 к 90-му), потом 1.02^L. В связке с `MAX_SAFE_INTEGER`-потолками это даёт «биллионы Data» и длинные числа в UI (формат `1,2 млрд` уже есть — ок, но читаемость падает).
→ Рассмотреть мягкий soft-cap награды миссий по Data (как сделано для `dataPerHour` в части карточек).

**F7 · P2 · Чипы — узкое место среднего этапа.**
45 чипов/сутки; тиры стоят 60/150/320, «База» — 1–2 чипа за уровень × 15 × 10 = ≈ 200. Итого ~12–14 дней только на чипы, независимо от Data.
→ Добавить чипы в ежедневный бонус/сезон или снизить стоимость апгрейдов Базы до 1 чипа на всех уровнях.

### 13.3 Глоссарий
- **Data** — основная валюта (оборотный капитал).
- **Energy** — лимит «работы»: 1 взлом стоит столько Energy, сколько длится в секундах.
- **Chips** — валюта глубоких апгрейдов, кап 45/сутки.
- **Crypto (💎)** — косметическая валюта, не сбрасывается престижем.
- **Heat** — розыск: >100 → штраф −10% Data и блок кликов 60 с.
- **Rep** — репутация: задаёт white_hat.
- **hackPower** — «сила железа», главный множитель шанса успеха.
- **Global Hack (престиж)** — сброс карточек/уровня за множитель дохода.
- **Тир карточек** — глобальный уровень прокачки (15/30/45/60).
- **База** — 10 пассивных апгрейдов, не сбрасываются престижем.
- **Слот миссии** — одновременный контракт; 1 → 2 (10 ур.) → 3 (20 ур.).
- **Скан сети (refresh)** — смена витрины миссий; `skip` стоит 1 💎.
